# ADR-0008: pgvector for embeddings & semantic search

**Status:** Accepted · **Date:** 2026-07-16 · **Phase:** 2

## Context
Semantic search (FR-TOOLS-3) and Ember's RAG grounding (FR-TUTOR-6) need vector similarity over
~10⁴–10⁵ chunks (240 lessons + glossary + questions). Dedicated vector DBs (Qdrant, Milvus,
Weaviate) add a stateful service to a Docker-free ops budget.

## Decision
PostgreSQL + **pgvector** (HNSW index, cosine). Hybrid retrieval: PG full-text search (tsvector,
websearch parser) ∪ vector top-k, reciprocal-rank-fusion re-rank in the API, lesson-scope boost
when asked from within a lesson. Embeddings generated by the `ai` Celery queue on content
publish; model configurable (OpenAI-compatible endpoint or local SentenceTransformers).

## Consequences
- ✅ Zero new services; transactional consistency between content rows and their vectors; one backup stream.
- ✅ Corpus is orders of magnitude below pgvector's practical ceiling (~10⁶–10⁷ with HNSW).
- ⚠️ If v2 adds learner-generated corpora at scale, revisit with a read-replica or dedicated store — retrieval sits behind a `Retriever` interface to keep that swap local.

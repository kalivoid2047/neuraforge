<h2 id="intuition">The matrix equivalent of "1" and "1/x"</h2>

Ordinary numbers have a multiplicative identity (1 — multiplying by it changes nothing) and,
for nonzero numbers, an inverse (1/x — multiplying by it gets you back to 1). Matrices have
direct analogs: the **identity matrix** and, for certain square matrices, an **inverse**. Both
turn out to be exactly what you need to solve systems of linear equations — the core operation
behind this month's Matrix Calculator project.

<h2 id="math">Identity and inverse, defined</h2>

The identity matrix `I` has 1s on the diagonal and 0s everywhere else. For any compatible
matrix `A`:

<MathBlock tex="AI = IA = A \qquad \text{(multiplying by } I \text{ changes nothing, just like } \times 1\text{)}" />

The **inverse** of a square matrix `A`, written `A⁻¹`, is the matrix satisfying:

<MathBlock tex="AA^{-1} = A^{-1}A = I" />

Not every square matrix has an inverse — a matrix without one is called **singular**. A system
of linear equations `Ax = b` (where `A` and `b` are known, `x` is the unknown vector you're
solving for) can be solved directly if `A` is invertible:

<MathBlock tex="Ax = b \;\;\Longrightarrow\;\; x = A^{-1}b" />

<Callout kind="warning" title="In practice, avoid computing the inverse explicitly">
  `x = A⁻¹b` is the clearest way to *understand* solving a linear system, and it's exactly what
  you'll implement for the Matrix Calculator. But for large, real systems, `np.linalg.solve(A, b)`
  is both faster and more numerically stable than computing the full inverse and then
  multiplying — it solves the system directly without the extra, more error-prone step of
  fully inverting `A`. Know both; prefer `solve` in production code.
</Callout>

## Summary

The identity matrix is multiplication's "do nothing" element; a square matrix's inverse (when
it exists) undoes multiplication by it, satisfying `AA⁻¹ = I`. A system of linear equations
`Ax = b` solves directly as `x = A⁻¹b` when `A` is invertible — matrices with linearly dependent
rows/columns (Week 3's concept, resurfacing here) are singular and have no inverse. In practice,
`np.linalg.solve` is preferred over explicitly computing an inverse, for both speed and
numerical stability.

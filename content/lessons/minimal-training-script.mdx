<h2 id="intuition">Closing week two: every piece, assembled</h2>

Month 3 closed its training-loop lesson with a five-step loop: forward pass, compute loss, zero
gradients, backward pass, update weights. Nothing about that structure has changed — what's
changed this week is *which tools* fill each step: `nn.Module`-style layers instead of hand-
written `Neuron`/`Layer` classes, cross-entropy instead of MSE (because this is a
classification problem now), and Adam instead of plain gradient descent. This lesson assembles
all of it into one script and trains a real (if small) classifier.

<h2 id="math">The real PyTorch version</h2>

```python
# reference only -- torch isn't available in this browser sandbox
import torch
import torch.nn as nn
import torch.optim as optim

model = nn.Sequential(nn.Linear(2, 8), nn.ReLU(), nn.Linear(8, 2))
loss_fn = nn.CrossEntropyLoss()
optimizer = optim.Adam(model.parameters(), lr=0.01)

for epoch in range(200):
    logits = model(x_batch)              # 1. forward pass
    loss = loss_fn(logits, y_batch)      # 2. compute loss
    optimizer.zero_grad()                # 3. zero gradients
    loss.backward()                      # 4. backward pass
    optimizer.step()                     # 5. update weights (Adam's rule, applied automatically)
```

Every line maps directly onto a concept already verified from scratch this week: `nn.Sequential`
chains layers (week 2, lesson 2); `CrossEntropyLoss` is softmax + `-log(p)` (lesson 3);
`optim.Adam` is the bias-corrected update rule (lesson 4); `.zero_grad()`/`.backward()` are
exactly Month 3's accumulation-reset and reverse-mode walk.

<Callout kind="tip" title="Every line here has a name in the reference PyTorch script above">
  `forward(X)` is `model(x_batch)`. The cross-entropy computation is `loss_fn(logits, y_batch)`.
  Building a fresh `grads` dict each iteration is what `optimizer.zero_grad()` +
  `loss.backward()` do together (compute fresh gradients, with nothing left over from the
  previous step). The Adam update loop over `params` is exactly `optimizer.step()`. Nothing here
  is a simplification of the *algorithm* — only of *who writes the derivative code*: PyTorch
  writes it once, correctly, for every operation, so you never have to.
</Callout>

## Week two summary

This week replaced Month 3's hand-written pieces with the real tools PyTorch provides:
`nn.Module`'s automatic parameter registration, `nn.Linear`/activation layers, cross-entropy
loss for classification, and the Adam optimizer — each verified from scratch, then assembled
into a complete training script that actually learns to separate two classes. The underlying
five-step loop from Month 3 never changed; only the building blocks filling each step did. Week
three turns to the practical concerns of *using data* responsibly: datasets, train/validation
splits, and regularization techniques that prevent a network from simply memorizing its
training data.

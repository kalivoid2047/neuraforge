<h2 id="intuition">A soft dictionary lookup</h2>

A normal Python dictionary lookup is exact: you have a **key** (`"apple"`), you compare it
against the dict's keys, and you get back exactly one **value**. Attention generalizes this to
be *soft*: instead of an exact match, every key gets a relevance *score* against your **query**,
those scores become weights (via softmax), and you get back a **weighted blend of every value**
— not just one.

<Callout kind="tip" title="The three roles">
  **Query** — "what am I looking for, right now?" (one per output position)
  **Key** — "what do I contain, that a query might match against?" (one per input position)
  **Value** — "what do I actually hand back, once matched?" (one per input position)
</Callout>

Critically: Q, K, and V are **three different linear projections of the same input** — not
three different pieces of data. Every token produces its own query, its own key, *and* its own
value, all from the same embedding, via three separate learned weight matrices.

<h2 id="math">The math</h2>

Given an input matrix `X` of shape `(seq_len, d_model)` — one embedding row per token — the
three projections are:

<MathBlock tex="Q = XW^{Q}, \qquad K = XW^{K}, \qquad V = XW^{V}" />

where `W^Q, W^K, W^V` are learned weight matrices of shape `(d_model, d_k)`. Nothing here is
attention *yet* — this is purely the setup. The next lesson takes these three matrices and
computes actual attention scores and outputs.

<Callout kind="warning" title="Why not just use X three times?">
  If Q, K, V were all literally `X` (no separate projections), a token could only ever match
  against tokens that look exactly like itself in embedding space — there'd be no way to learn
  "pronouns should attend to nouns" or any other *asymmetric* relationship. Three independent
  learned projections let the model learn what to search for (Q), what to be found by (K), and
  what to actually retrieve (V) — three different jobs.
</Callout>

## Summary

Every token in a sequence produces three vectors — a query, a key, and a value — each via its
own learned linear projection of the same input embedding. The query asks "what am I looking
for," the key answers "here's what I offer," and the value is "here's what you actually get if
matched." The next lesson turns these three into the actual attention computation.

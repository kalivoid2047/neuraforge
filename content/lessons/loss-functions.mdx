<h2 id="intuition">A single number measuring "how wrong," ready to be minimized</h2>

Every forward pass so far has produced an output. To actually train a network (Month 3), you
need a single number — the **loss** — measuring how wrong that output is compared to the true
answer, small when the prediction is good and large when it's bad. Different task types need
genuinely different loss functions, matched to what "wrong" even means for that task.

<h2 id="math">Cross-entropy (classification) and MSE (regression)</h2>

For classification, with true class `y` and predicted probability distribution `ŷ` (softmax
output):

<MathBlock tex="\mathcal{L}_{\text{CE}} = -\log(\hat{y}_y) \qquad \text{(negative log-probability the model assigned to the TRUE class)}" />

This is small when the model assigns high probability to the correct class, and grows sharply
(toward infinity) as the assigned probability toward the correct class approaches zero — a
strong penalty for confident wrong answers, not just wrong ones.

For regression, with true value `y` and predicted value `ŷ`:

<MathBlock tex="\mathcal{L}_{\text{MSE}} = (\hat{y} - y)^2" />

Squaring makes the loss always non-negative and penalizes larger errors disproportionately more
than smaller ones — being off by 10 costs 100x more than being off by 1, not just 10x more.

<Callout kind="warning" title="Why the pairing (loss <-> activation) matters">
  Cross-entropy is specifically designed to pair with a softmax (or sigmoid, for binary)
  output — it directly penalizes the assigned probability of the true class, which only makes
  sense when the output IS a probability distribution. Using MSE on a classification task (or
  cross-entropy on a raw regression output) is a real, common mistake — the loss and the
  output's meaning have to match, or the resulting gradients (Month 3) push training in a less
  useful direction.
</Callout>

## Summary

Cross-entropy loss (`-log(ŷ_true_class)`) is the standard choice for classification, penalizing
confident wrong predictions especially sharply; mean squared error (`(ŷ − y)²`) is the standard
for regression, penalizing large errors disproportionately more than small ones. Matching loss
function to task type and output activation isn't a stylistic choice — using the wrong pairing
produces a genuinely less useful training signal. This closes the toolkit; the capstone lesson
assembles a forward pass, an architecture, and this loss computation into a complete, if not
yet trainable, network.

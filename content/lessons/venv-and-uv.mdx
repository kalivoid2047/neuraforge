<h2 id="intuition">One computer, many projects, conflicting needs</h2>

Say Project A needs NumPy 1.24, and Project B needs NumPy 2.0. If you install packages
"globally" (system-wide), you can only have one version at a time — installing B's version
breaks A. A **virtual environment** is an isolated, self-contained Python installation *per
project*: each project gets its own private set of installed packages, with zero risk of one
project's dependencies clashing with another's.

<Callout kind="tip" title="The core idea, in one sentence">
  A virtual environment is a folder containing a private copy of Python and its installed
  packages, activated per-project, so different projects never fight over dependency versions.
</Callout>

<h2 id="lockfiles">Dependencies vs. locked versions</h2>

Real projects distinguish two related but different files:

- **`pyproject.toml`** — states *what* your project depends on, often with a version range
  (`numpy>=2.1`). This is what a human edits.
- **`uv.lock`** — records the *exact* version of every package (and every dependency of every
  dependency) that was actually resolved and installed, down to the exact build. This is what a
  machine generates and everyone else's environment is built from, guaranteeing you get
  identical results to your teammates.

<Callout kind="history" title="Why uv, and why not Docker?">
  This course — and the Neuraforge platform you're using right now — deliberately avoids Docker
  for environment management (see ADR-0002 in the platform's own architecture docs). `uv`
  (a modern, extremely fast Python package/environment manager) gives the same reproducibility
  guarantee — an exact, locked dependency set, byte-for-byte reproducible on any machine —
  without the overhead of containers. For a single-language Python project, a lockfile plus a
  virtual environment already solves the reproducibility problem Docker is often reached for.
</Callout>

## Summary

Virtual environments isolate a project's installed packages from the rest of the system and
from other projects, preventing dependency version conflicts. `pyproject.toml` declares what a
project needs (as ranges); `uv.lock` pins exactly what was resolved, guaranteeing byte-identical
environments across machines — the same reproducibility goal Docker is often used for, achieved
here without containers.

<h2 id="intuition">One head is a spotlight. You need a lighting rig.</h2>

A single attention head computes *one* notion of relevance: perhaps "which earlier word does
this pronoun refer to?" But language needs many notions *at once* — syntax, coreference,
position, topic. Multi-head attention runs `h` small attention operations in parallel, each in
its own learned subspace, then concatenates what they found.

<Callout kind="tip" title="The core intuition">
  Don't think "8 copies of the same thing." Think 8 *specialists*, each with a cheap,
  low-dimensional view — a syntax head, a coreference head, a position head — whose reports are
  stitched together.
</Callout>

<h2 id="history">History</h2>

<Callout kind="history" title='2017 — "Attention Is All You Need"'>
  Vaswani et al. found that multiple heads let the model attend to information from different
  representation subspaces at different positions — with *the same total compute* as one big
  head, because each head works in dimension d_model/h.
</Callout>

<h2 id="math">The math, derived</h2>

Recall single-head attention. With queries Q, keys K, and values V:

<MathBlock tex="\mathrm{Attention}(Q,K,V)=\mathrm{softmax}\!\left(\frac{QK^{\top}}{\sqrt{d_k}}\right)V" />

Multi-head splits the model dimension into `h` subspaces. Head `i` gets its own learned
projections:

<MathBlock tex="\mathrm{head}_i=\mathrm{Attention}(XW_i^{Q},\,XW_i^{K},\,XW_i^{V}),\qquad W_i^{Q},W_i^{K},W_i^{V}\in\mathbb{R}^{d_{\text{model}}\times d_k}" />

<MathBlock tex="\mathrm{MultiHead}(X)=\mathrm{Concat}(\mathrm{head}_1,\dots,\mathrm{head}_h)\,W^{O},\qquad d_k=\frac{d_{\text{model}}}{h}" />

Every equation above is just matrix multiplication — the operation you mastered in Month 1.

<h2 id="python">Pure Python first. Always.</h2>

Before PyTorch does it for you, build it yourself. Edit and run — the shapes are the whole
story:

<CodeCell
  code={`import numpy as np\n\ndef softmax(x, axis=-1):\n    x = x - x.max(axis=axis, keepdims=True)\n    e = np.exp(x)\n    return e / e.sum(axis=axis, keepdims=True)\n\ndef attention(Q, K, V):\n    d_k = K.shape[-1]\n    scores = Q @ K.T / np.sqrt(d_k)\n    weights = softmax(scores, axis=-1)\n    return weights @ V, weights\n\ndef multi_head_attention(X, Wq, Wk, Wv, Wo, h):\n    seq, d_model = X.shape\n    d_k = d_model // h\n    heads = []\n    for i in range(h):\n        Q = X @ Wq[i]; K = X @ Wk[i]; V = X @ Wv[i]\n        out, _ = attention(Q, K, V)\n        heads.append(out)\n    concat = np.concatenate(heads, axis=-1)\n    return concat @ Wo\n\nnp.random.seed(0)\nseq, d_model, h = 6, 512, 8\nd_k = d_model // h\nX = np.random.randn(seq, d_model)\nWq = np.random.randn(h, d_model, d_k) * 0.02\nWk = np.random.randn(h, d_model, d_k) * 0.02\nWv = np.random.randn(h, d_model, d_k) * 0.02\nWo = np.random.randn(d_model, d_model) * 0.02\n\nout = multi_head_attention(X, Wq, Wk, Wv, Wo, h)\nprint("input ", X.shape)\nprint("output", out.shape)`}
  output={"input  (6, 512)\noutput (6, 512)"}
/>

<Callout kind="warning" title="Common bug">
  If your softmax normalizes over the *query* axis instead of the *key* axis, rows won't sum to
  1 and training silently diverges. Check `np.allclose(weights.sum(-1), 1.0)`.
</Callout>

## Summary

Multi-head attention runs `h` independent attention operations in parallel subspaces of size
`d_model/h`, then concatenates and projects the result. It costs the same as one big head but
lets different heads specialize — syntax, coreference, position — which a single head cannot do
simultaneously.

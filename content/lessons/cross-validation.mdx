<h2 id="intuition">One train/test split is one noisy sample</h2>

Month 4's train/validation split, evaluated once, gives a single performance number — but that
number depends partly on which particular examples happened to land in the validation set. A
"lucky" or "unlucky" split can make a model look better or worse than it really is, especially
with small datasets like this month's text examples. **Cross-validation** fixes this by
evaluating on *several* different splits and averaging, giving a far more reliable estimate of
how a model actually performs.

<h2 id="math">K-fold cross-validation</h2>

Split the dataset into `k` roughly equal parts ("folds"). For each fold in turn: train on the
other `k-1` folds, evaluate on the held-out fold. Average the `k` resulting scores:

<MathBlock tex="\text{CV score} = \frac{1}{k}\sum_{i=1}^{k} \text{score}(\text{model trained on folds} \neq i,\ \text{evaluated on fold } i)" />

Every example gets used for evaluation *exactly once*, across the `k` folds, and for training in
every fold except the one where it's held out — making full use of a small dataset rather than
permanently sacrificing one chunk of it as a single validation set.

<Callout kind="tip" title="Cross-validation isn't just 'more data' -- it reduces the estimate's VARIANCE">
  Averaging `k` scores from `k` different splits doesn't just use more data efficiently — it
  directly reduces how much the *final reported number* varies from one lucky-or-unlucky split
  to another (an application of the same "averaging reduces variance" idea behind the Law of
  Large Numbers, week one). The code below demonstrates this directly: single splits scatter
  much more widely than the cross-validated average.
</Callout>

<h2 id="python">K-fold cross-validation, implemented and compared to single splits</h2>

  code={"import numpy as np\n\ndef k_fold_indices(n, k, seed=0):\n    rng = np.random.default_rng(seed)\n    indices = np.arange(n)\n    rng.shuffle(indices)\n    folds = np.array_split(indices, k)\n    return folds\n\n# a toy 'classifier': predicts correctly with some fixed underlying probability\ndef simulate_accuracy(rng, n_test, true_accuracy):\n    correct = rng.random(n_test) < true_accuracy\n    return correct.mean()\n\nrng = np.random.default_rng(1)\nn_examples = 40\ntrue_underlying_accuracy = 0.75   # the model's REAL performance, which we're trying to estimate\n\n# approach 1: many independent SINGLE train/test splits (80/20), each giving one noisy estimate\nsingle_split_scores = []\nfor trial in range(20):\n    test_size = int(n_examples * 0.2)\n    score = simulate_accuracy(rng, test_size, true_underlying_accuracy)\n    single_split_scores.append(score)\n\nprint(\"20 independent single 80/20 splits:\")\nprint(\"  scores:\", [round(float(s), 3) for s in single_split_scores[:8]], \"...\")\nprint(f\"  mean: {np.mean(single_split_scores):.4f}  std: {np.std(single_split_scores):.4f}\")\nprint()\n\n# approach 2: 5-fold cross-validation, repeated 20 times (20 different random fold assignments)\ncv_scores = []\nfor trial in range(20):\n    folds = k_fold_indices(n_examples, k=5, seed=trial)\n    fold_scores = [simulate_accuracy(rng, len(fold), true_underlying_accuracy) for fold in folds]\n    cv_scores.append(np.mean(fold_scores))   # average across the 5 folds -- THIS is the CV score\n\nprint(\"20 independent 5-fold CV estimates (each averaging 5 folds):\")\nprint(\"  scores:\", [round(float(s), 3) for s in cv_scores[:8]], \"...\")\nprint(f\"  mean: {np.mean(cv_scores):.4f}  std: {np.std(cv_scores):.4f}\")\nprint()\nprint(f\"true underlying accuracy: {true_underlying_accuracy}\")\nprint(f\"CV estimates are noticeably LESS spread out (smaller std) than single-split estimates,\")\nprint(f\"even though both average out to roughly the same true value.\")"}

## Summary

K-fold cross-validation splits data into `k` folds, training on `k-1` and evaluating on the
held-out fold each time, then averages the `k` scores — giving a performance estimate that
varies far less from one random split to another than a single train/test split does, verified
directly above by comparing the spread of repeated single-split scores against repeated
cross-validation scores. This is exactly the methodology used to reliably compare models or
tune hyperparameters, rather than trusting one arbitrary split's result. The next lesson bridges
this month's classical NLP techniques to Month 4's neural network tools, building a neural text
classifier directly on top of the bag-of-words representation.

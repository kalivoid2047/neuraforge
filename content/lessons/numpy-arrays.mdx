<h2 id="intuition">One data type, packed tightly, operated on in bulk</h2>

A NumPy array (`ndarray`) is a grid of values, **all of the same data type**, stored in one
contiguous block of memory. That single constraint — uniform dtype — is exactly what makes it
fast: NumPy knows in advance exactly how many bytes each element takes and can hand the whole
block to highly optimized, compiled code that processes it in bulk, instead of Python having to
check each element's type one at a time.

<Callout kind="tip" title="The trade you're making">
  A Python list can hold `[1, "two", 3.0, [4]]` — anything, mixed. A NumPy array cannot; every
  element shares one dtype (usually a fixed-size number type like `float64` or `int32`). You
  give up flexibility and get speed and memory efficiency in return — the right trade for
  numerical data, the wrong trade for a general-purpose container.
</Callout>

<Callout kind="danger" title="Pitfall: * is element-wise, not matrix multiplication">
  `a * b` between two arrays multiplies corresponding elements — it is **not** matrix
  multiplication, even for 2D arrays. Matrix multiplication uses `@` or `np.matmul()`, covered
  in Week 4. Using `*` when you meant `@` is one of the most common NumPy bugs beginners hit,
  and it usually doesn't crash — it just silently computes the wrong thing.
</Callout>

## Summary

NumPy arrays store elements of one uniform dtype in contiguous memory, which lets bulk
operations run in optimized compiled code rather than a Python-level loop. Element-wise
operators (`+`, `*`, `**`, comparisons) apply position-by-position across arrays — note
carefully that `*` is element-wise multiplication, not matrix multiplication, which you'll meet
properly in Week 4.

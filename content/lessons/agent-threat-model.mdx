<h2 id="intuition">Week four: a model that can act is a different security problem</h2>

A chatbot that says something wrong has said something wrong. An agent that concludes something wrong **acts on it** — deletes the index, sends the email, files the ticket. Every safety property that was advisory becomes load-bearing.

<h2 id="math">Capability, Autonomy, Untrusted Input</h2>

Three properties together create the risk; any two are manageable:

1. **Capability** — the agent can cause side effects.
2. **Autonomy** — it acts without per-action human approval.
3. **Untrusted input** — it processes content the operator did not write.

This is the classic **confused deputy**: a privileged component induced to misuse its authority on behalf of someone who lacks it. The agent is not compromised and the model is not "jailbroken" — it is doing exactly what it was asked, by the wrong party.

<Callout kind="tip" title="Remove any one of the three and the risk collapses">
  A read-only agent has no capability, so untrusted input cannot hurt. An agent that confirms every side effect has no autonomy, so a bad decision is caught. An agent that touches only operator-authored content has no untrusted input. Each of these is a real design, and each is cheaper than trying to make a model reliably resist persuasion. **Design the capability away before trying to defend it.**
</Callout>

## Summary

Agents combine capability, autonomy, and untrusted input; any two are manageable and all three create a confused deputy — a privileged component induced to misuse its authority. This is not a jailbreak and not an alignment failure, and the framing matters because it points at different fixes. Removing any one of the three properties collapses the risk, and doing so is cheaper than making a model resist persuasion. The next lesson shows the attack.

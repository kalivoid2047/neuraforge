<h2 id="intuition">The data structure that makes the chain rule automatable</h2>

Every expression you compute — even something as simple as `z = (x + y) * x` — is secretly a
sequence of tiny, individual operations: an addition, then a multiplication. A **computational
graph** makes this explicit: each node is one primitive operation, and edges show which values
feed into which operations. This is the data structure that PyTorch, TensorFlow, and every
other autograd system builds internally, and it's exactly what you'll implement by hand next
week.

<h2 id="math">Building the graph for z = (x + y) * x</h2>

Break the expression into primitive steps, naming each intermediate result:

<MathBlock tex="a = x + y \qquad z = a \cdot x" />

This gives two nodes: `a` (an addition of `x` and `y`) and `z` (a multiplication of `a` and
`x` — note `x` is used *twice*, feeding into both nodes). Drawn as a graph, `x` and `y` are
leaf nodes (no inputs), `a` is an intermediate node depending on `x` and `y`, and `z` is the
final output node depending on `a` and `x`.

<Callout kind="tip" title="Why bother building an explicit graph?">
  Because the chain rule needs to know exactly which quantities depend on which other
  quantities, and through which paths. The graph makes every dependency and every path
  explicit and traversable by an algorithm — instead of a human working out by hand which
  terms to add (like the multivariable chain rule two lessons ago), the graph lets a program
  walk the dependency structure automatically. That automated walk, done backward from the
  output, is exactly what backpropagation is.
</Callout>

## Summary

A computational graph breaks an expression into primitive operations as nodes, with edges
showing which values feed into which operations — exactly the structure that autograd engines
build and traverse. A variable used multiple times appears as an input to multiple nodes, which
matters directly for the next lesson: computing gradients requires summing contributions from
every node that used a given value, mirroring the "sum over paths" idea from the multivariable
chain rule.

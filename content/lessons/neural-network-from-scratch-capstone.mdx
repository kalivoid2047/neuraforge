<h2 id="intuition">Everything this month, assembled and tested</h2>

This capstone combines every piece from the last four weeks: an MLP architecture (week four),
ReLU and softmax activations (week three), matrix-vectorized layers built on Month 1's linear
algebra, and cross-entropy loss (this week) — wrapped in the tests Month 1's Week 2 taught you
to write. What it does *not* yet do is learn: adjusting weights to reduce the loss requires
gradients and backpropagation, which is next month's entire subject. This is a complete,
correct, tested forward-pass network — the "does it compute the right thing, for given weights"
half of a neural network, not yet the "does it learn good weights" half.

<h2 id="python">A complete, tested MLP with loss computation</h2>

<h2 id="scope">What this can't do yet, and why that's OK</h2>

<Callout kind="warning" title="This network cannot learn -- yet, by design">
  Every weight above comes from random initialization and stays exactly there — there is no
  mechanism in this lesson's code for the loss to actually decrease over time. That requires
  computing *how* each weight should change to reduce the loss (its gradient), which requires
  backpropagation: the calculus (Month 3 opens with derivatives and the chain rule) that makes
  gradient computation for an arbitrarily deep network tractable. This capstone deliberately
  stops at "correct, tested, forward computation" — that boundary is not a shortcut, it's
  exactly where this month's material ends and next month's begins.
</Callout>

## Summary

This capstone assembles a complete, tested feedforward classifier — configurable architecture,
matrix-vectorized layers, ReLU/softmax activations, and cross-entropy loss — verified with the
same Arrange-Act-Assert testing discipline Month 1 established. It deliberately does not learn:
weights are fixed at random initialization, and turning this into a trainable network requires
backpropagation, which is the entire subject of Month 3, starting with derivatives and the
chain rule.

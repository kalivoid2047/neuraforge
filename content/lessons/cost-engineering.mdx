<h2 id="intuition">The same model and hardware, 36x apart on price</h2>

For a self-hosted model, unit cost is not a pricing decision — it is arithmetic. You rent the hardware by the hour and divide by how many tokens it produced, which makes every throughput optimization from week one directly a cost optimization.

<h2 id="math">Throughput Is Cost</h2>

<MathBlock tex="\text{cost per } 10^6 \text{ tokens} = \frac{\text{\$ per hour}}{\text{tokens per second} \times 3600} \times 10^6" />

The hardware price is fixed; throughput is the only variable. So the configuration choices from week one — batch size, continuous batching, quantization — are the entire cost lever, and they compound.

<Callout kind="tip" title="36x on unit cost, from configuration alone">
  The measured table spans **$13.23** per million tokens at batch 1 in fp16 down to **$0.37** at batch 32 with int4 and continuous batching — **36×** apart, on identical hardware running the identical model. None of it came from a faster GPU. It came from batching (week one) and quantization (Month 9). Serving efficiency is not a micro-optimization; it is frequently the difference between a viable product and one that loses money per request.
</Callout>

<Callout kind="warning" title="A model, not a benchmark">
  There is no GPU or web server in this browser, so the numbers below come from an explicit
  cost *model* — stated constants for service time, throughput and price — not from a
  measurement of real hardware. That is the honest framing, and it is also how capacity planning
  is actually done before the hardware is bought. What the cell demonstrates is the **shape** of
  the trade: which way each curve bends, and where it goes vertical. Substitute your own measured
  constants and the conclusions follow the same shape.
</Callout>

## Summary

Self-hosted unit cost is hardware price divided by throughput, which makes every week-one optimization a cost optimization. Measured, the same model on the same hardware spans **$13.23** to **$0.37** per million tokens — **36×** — from batching and quantization alone. But the cheapest rows get there partly through quantization, which Month 9 measured as introducing error, so a cost table without a quality table beside it is an invitation to ship a regression as a win.

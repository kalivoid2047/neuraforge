<h2 id="intuition">The model has no reason to remember what you stopped asking about</h2>

Gradient descent minimizes the loss it is *given*. During fine-tuning that loss is computed entirely on the new task, so nothing in the objective assigns any value to the old capability. Weights that were essential to task A but unhelpful for task B are free to move, and they do. This is **catastrophic forgetting**, and it is not a bug — it is the optimizer doing exactly what was asked.

<h2 id="math">Why Gradient Descent Forgets</h2>

Pretraining found `θ*` minimizing `L_A`. Fine-tuning minimizes `L_B` alone:

<MathBlock tex="\theta_{\text{final}} = \arg\min_\theta \mathcal{L}_B(\theta) \qquad \text{with no term for } \mathcal{L}_A" />

The mitigations all work by putting `L_A` back into the objective in some form — explicitly (replay the old data), implicitly (penalize moving far from `θ*`), or structurally (make most of `θ` unmovable, which is week two's approach).

<Callout kind="warning" title="Forgetting the readout and degrading the representation are different failures">
  The experiment below separates them. Both methods lose task A's accuracy, because both retrain the shared output head. But re-fitting a *fresh* head on top of each backbone reveals what actually survived: the frozen backbone recovers task A to **1.000**, while the fully fine-tuned backbone only reaches **0.912**. Full fine-tuning did not just overwrite the readout — it degraded the underlying features, which is the damage that is genuinely hard to undo.
</Callout>

<Callout kind="tip" title="The standard mitigations">
  **Replay / rehearsal** — mix pretraining data into the fine-tuning set so `L_A` stays in the
  objective. Effective, but requires access to the pretraining distribution. **Regularization**
  (EWC, L2-to-init) — add a penalty for moving far from `θ*`, weighted by how important each
  weight was. **Lower learning rates and fewer epochs** — the cheapest mitigation and often
  enough. **Freezing or adapters** — make most parameters structurally unable to move, which is
  what LoRA does and why week two matters for more than memory.
</Callout>

## Summary

Catastrophic forgetting happens because the fine-tuning objective contains no term for the old capability, so weights essential to it are free to move. Measured here, full fine-tuning took task A from 1.000 to 0.172. The recovery test separates two distinct failures: both methods lose the shared readout, but only full fine-tuning degrades the representation — 0.912 recovery versus the frozen backbone's 1.000. Mitigations all amount to reintroducing the old objective, whether by replay, regularization, or structurally freezing weights. The next lesson takes that last route.

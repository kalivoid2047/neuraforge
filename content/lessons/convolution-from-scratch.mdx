<h2 id="intuition">Week four: a layer designed specifically for image-shaped data</h2>

Every layer so far (`nn.Linear`) treats its input as a flat vector, with no notion of "nearby"
pixels being related. For images, that throws away enormously useful structure — a cat's ear
looks like a cat's ear regardless of *where* in the image it appears, and nearby pixels are far
more related to each other than distant ones. **Convolution** is a layer designed around
exactly this: a small learnable **kernel** (a tiny grid of weights, e.g. 3×3) slides across the
whole image, computing a dot product at every position — the *same* small set of weights,
reused at every location, looking for the *same* pattern wherever it appears.

<h2 id="math">Sliding, multiplying, summing</h2>

At each position, take the dot product of the kernel with the corresponding patch of the input:

<MathBlock tex="\text{output}_{i,j} = \sum_{m}\sum_{n} \text{kernel}_{m,n} \cdot \text{input}_{i+m,\,j+n}" />

Slide the kernel across every valid position, and the collection of these dot products forms
the output — called a **feature map**, because each value measures how strongly the kernel's
pattern matched that location.

```python
# reference only -- torch isn't available in this browser sandbox
import torch.nn as nn

conv = nn.Conv2d(in_channels=1, out_channels=1, kernel_size=3)
# conv.weight has shape (1, 1, 3, 3) -- just 9 learnable numbers, reused at every position
```

<Callout kind="tip" title="Why this needs far fewer parameters than a fully-connected layer">
  A fully-connected (`nn.Linear`) layer mapping a 28×28 image (784 pixels) to another 28×28
  output would need 784×784 ≈ 614,000 weights. A 3×3 convolution needs just **9** weights,
  reused at every position — because the same small pattern-detector is applied everywhere,
  rather than learning an entirely separate weight for every possible pixel-to-pixel
  connection. This isn't just a memory saving: it directly encodes the assumption that useful
  patterns (edges, textures) look the same regardless of where they appear in the image.
</Callout>

## Summary

Convolution slides a small learnable kernel across an input, computing a dot product (multiply
elementwise, then sum) at every position, producing a feature map that responds strongly
wherever the kernel's pattern is present — verified above with a hand-checked vertical-edge
detector. Because the same small kernel is reused at every position, convolution needs
dramatically fewer parameters than a fully-connected layer would for image-sized input, while
directly encoding the assumption that useful visual patterns look the same regardless of
location. The next lesson covers pooling, the operation typically paired with convolution to
progressively shrink feature maps.

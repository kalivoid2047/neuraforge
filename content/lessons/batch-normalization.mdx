<h2 id="intuition">Closing week three: stabilizing what each layer actually sees</h2>

As a network trains, every layer's *input* distribution keeps shifting — earlier layers'
weights are changing too, on every step, so a layer that was seeing roughly zero-centered
inputs last epoch might see something quite differently-scaled this epoch. This forces every
layer to constantly re-adapt to a moving target, which slows training. **Batch normalization**
stabilizes this: within each batch, force every layer's input to have zero mean and unit
variance, then let the network learn its own preferred scale and shift back on top of that
stable baseline.

<h2 id="math">Normalize, then rescale</h2>

For a batch of activations, per feature (across the batch dimension):

<MathBlock tex="\hat{x} = \frac{x - \mu_{\text{batch}}}{\sqrt{\sigma^2_{\text{batch}} + \epsilon}} \qquad y = \gamma \hat{x} + \beta" />

`μ` and `σ²` are the batch's own mean and variance (computed fresh each batch); `ε` is a tiny
constant preventing division by zero. `γ` and `β` are **learned parameters** — not fixed at `1`
and `0` — because forcing every layer's output to *exactly* zero mean and unit variance forever
would actually limit what the network can represent. Letting the network learn its own `γ`
(scale) and `β` (shift) means it can recover the original distribution *if that turns out to be
useful*, while still starting from a stable, well-behaved baseline every step.

```python
# reference only -- torch isn't available in this browser sandbox
import torch.nn as nn

model = nn.Sequential(nn.Linear(10, 20), nn.BatchNorm1d(20), nn.ReLU(), nn.Linear(20, 1))
# BatchNorm1d owns two learned parameter vectors: weight (gamma) and bias (beta), one value each per feature
```

<Callout kind="tip" title="Why gamma/beta being learnable matters">
  If `γ` and `β` were fixed forever at `1` and `0`, every batch-normalized layer's output would
  be *forced* to zero mean and unit variance, permanently — even in cases where a different
  scale would represent the data better. Making them learned parameters (updated by the exact
  same gradient descent + backward pass as every other weight) means the network can recover
  whatever scale and shift is actually useful, as verified above, while still benefiting from
  the stable, well-behaved starting point normalization provides every single batch.
</Callout>

## Week three summary

This week covered the practical machinery around training a real network responsibly: `Dataset`
and `DataLoader` separate what data is from how it's served, with per-epoch reshuffling
preventing order-dependent learning; train/validation/test splits reveal (and guard against)
overfitting that training accuracy alone would hide; and three regularization techniques —
weight decay (penalizing large weights), dropout (forcing redundancy via random deactivation),
and batch normalization (stabilizing each layer's input distribution) — each verified from
scratch to do exactly what their math claims. Week four builds convolutional layers and
assembles everything from this month into the Image Classifier capstone.

<h2 id="intuition">The same three ideas, now applied to whole matrices</h2>

Everything from Month 3's autograd engine still applies here, just at the tensor level:
`requires_grad=True` marks a tensor as "track operations on this" (like `Value.__init__`
always did implicitly); `.backward()` walks the recorded graph in reverse topological order; and
`.grad` accumulates the result. The only real difference worth calling out: because tensors can
hold whole matrices, a single `.backward()` call now computes the gradient of the loss with
respect to an *entire weight matrix* at once — not one scalar at a time.

<h2 id="math">Gradients of a linear layer</h2>

For a linear layer `y = xW + b` (a batch `x` of shape `(n, d_in)`, weights `W` of shape
`(d_in, d_out)`, bias `b` of shape `(d_out,)`), with a scalar loss `L` computed from `y`, the
gradients needed to update `W` and `b` are:

<MathBlock tex="\frac{\partial L}{\partial W} = x^\top \frac{\partial L}{\partial y} \qquad \frac{\partial L}{\partial b} = \sum_{i=1}^{n} \frac{\partial L}{\partial y_i}" />

These follow from the multivariable chain rule (Month 3, week 2) applied to matrix
multiplication and broadcasting — `∂L/∂b` sums over the batch dimension precisely because
broadcasting (last lesson) *used* the same `b` for every row, so every row's gradient
contribution flows back into that one shared `b`, exactly the "multi-use value sums its
gradient" rule from Month 3.

```python
# reference only -- torch isn't available in this browser sandbox
import torch

x = torch.randn(4, 3, requires_grad=False)      # a batch of 4 examples, 3 features each
W = torch.randn(3, 2, requires_grad=True)        # weights: 3 in-features -> 2 out-features
b = torch.zeros(2, requires_grad=True)

y = x @ W + b                # linear layer forward pass, broadcasting b across the batch
loss = (y ** 2).sum()         # a toy scalar loss
loss.backward()

print(W.grad.shape)  # torch.Size([3, 2]) -- one gradient value per weight
print(b.grad.shape)  # torch.Size([2])
```

<Callout kind="tip" title="This is what nn.Linear + .backward() do for you automatically">
  Every step above — the forward matrix multiply, the analytical gradient derivation, applying
  the chain rule through broadcasting — is exactly what `torch.nn.Linear` plus `.backward()`
  perform automatically, for layers of any size, in one line each. Deriving it by hand once, and
  verifying it numerically, is what makes trusting the automated version reasonable — the same
  reason Month 3 insisted on numerical gradient checks for the hand-built engine.
</Callout>

## Summary

Tensor-level autograd applies exactly the same reverse-mode mechanism from Month 3, just to
whole matrices at once: `∂L/∂W = xᵀ(∂L/∂y)` and `∂L/∂b = Σ(∂L/∂y)`, with the sum in the bias
gradient arising directly from broadcasting reusing `b` across every row in the batch — the
same "multi-use value sums its gradient" rule from Month 3's chain rule lessons. Verifying these
analytical gradients numerically is the same discipline used throughout last month, now applied
at the matrix level. The final lesson this week explains why any of this needs a GPU at all.

<h2 id="intuition">Entropy for two distributions: the true one, and your guess</h2>

Entropy measures the average bits needed to encode outcomes from a distribution `P`, *using an
optimal code built for P itself*. **Cross-entropy** asks a related but different question: what
if you encode outcomes from the true distribution `P`, but using a code that was optimized for
a *different*, possibly wrong distribution `Q` (your model's prediction)? The more `Q`
mismatches `P`, the more bits get wasted — cross-entropy is always at least as large as `P`'s
own entropy, and the gap is exactly how much your model's predictions cost you for being wrong.

<h2 id="math">Cross-entropy, defined</h2>

<MathBlock tex="H(P, Q) = -\sum_i P(i) \log_2 Q(i)" />

Compare this to entropy, `H(P) = -ΣP(i)log₂P(i)` — cross-entropy simply replaces the *second*
`P(i)` with `Q(i)`, the model's predicted probability, while still weighting by the *true*
probability `P(i)`. When a true label is one-hot (probability `1` on the correct class, `0`
everywhere else — exactly Month 4's classification setup), only one term in the sum survives:

<MathBlock tex="H(P,Q) = -1\cdot\log_2 Q(\text{correct class}) = -\log_2 Q(\text{correct class})" />

— exactly Month 4's `-log(p_correct)` cross-entropy loss (using the natural log there instead of
`log₂` is just a units choice — "nats" instead of "bits" — that doesn't change any of the
underlying behavior or the optimization).

<h2 id="python">Cross-entropy, verified, and its relationship to entropy</h2>

<CodeCell
  code={"import numpy as np\n\ndef entropy(p):\n    p = np.array(p)\n    nz = p[p > 0]\n    return -np.sum(nz * np.log2(nz))\n\ndef cross_entropy(p, q):\n    p, q = np.array(p), np.array(q)\n    mask = p > 0   # skip terms where p(i)=0 -- they contribute nothing regardless of q(i)\n    return -np.sum(p[mask] * np.log2(q[mask]))\n\n# true distribution: a fair coin\np_true = [0.5, 0.5]\n\n# three possible models (predicted distributions), of varying quality\nq_perfect = [0.5, 0.5]      # matches P exactly\nq_close = [0.6, 0.4]        # a bit off\nq_bad = [0.99, 0.01]        # confidently wrong about the balance\n\nprint(f\"H(P) [entropy of the true distribution]: {entropy(p_true):.4f} bits\")\nprint()\nfor name, q in [(\"perfect model\", q_perfect), (\"close model\", q_close), (\"bad model\", q_bad)]:\n    ce = cross_entropy(p_true, q)\n    gap = ce - entropy(p_true)\n    print(f\"{name:>13} Q={q}: H(P,Q) = {ce:.4f} bits   (gap over H(P): {gap:.4f})\")\n\nprint()\nprint(\"the gap is exactly zero only when Q matches P exactly -- otherwise cross-entropy\")\nprint(\"is STRICTLY greater than the true distribution's own entropy, and grows as Q gets worse.\")\nprint()\n\n# connect directly to Month 4's -log(p_correct) formula, for a one-hot true label\none_hot_true = [1.0, 0.0]      # 'true class is index 0', with total certainty\nmodel_prediction = [0.8, 0.2]  # model assigns 80% to the correct class\nce_onehot = cross_entropy(one_hot_true, model_prediction)\nmonth4_style = -np.log2(model_prediction[0])   # exactly Month 4's -log(p_correct), base-2 here\nprint(f\"one-hot cross-entropy: {ce_onehot:.4f} bits\")\nprint(f\"Month-4-style -log2(p_correct): {month4_style:.4f} bits\")\nprint(f\"identical: {np.isclose(ce_onehot, month4_style)}\")"}

<Callout kind="tip" title="This is exactly why cross-entropy loss can never go below zero">
  Since cross-entropy is always at least the true distribution's own entropy, and a one-hot true
  label has *zero* entropy (no uncertainty — `H([1,0]) = 0`, as verified last lesson), a
  classification model's cross-entropy loss is bounded below by exactly `0`, achieved only when
  the model assigns probability `1` to the correct class. This is a cleaner explanation of "loss
  can't go negative" than just accepting it as a property of the formula.
</Callout>

## Summary

Cross-entropy `H(P,Q) = -ΣP(i)log₂Q(i)` measures the cost (in bits) of encoding true-distribution
outcomes using a code optimized for a possibly-mismatched `Q` — always at least `H(P)` itself,
with the gap growing as `Q` worsens, verified directly above. For a one-hot true label, this
reduces exactly to Month 4's `-log(p_correct)` loss, now understood as a specific case of a more
general information-theoretic quantity rather than an arbitrary formula. The next lesson
isolates that "gap" itself — KL divergence — as its own named, useful quantity.

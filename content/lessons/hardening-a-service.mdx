<h2 id="intuition">A sandbox you get without Docker</h2>

Containers are the usual answer to "isolate this service", and this project deliberately does not use them. systemd provides most of the same isolation primitives directly — they are the same kernel features — configured in the unit file rather than in an image.

<h2 id="math">Least Privilege From the Init System</h2>

Each directive removes a specific capability:

- `ProtectSystem=strict` — the entire filesystem read-only except explicit exceptions.
- `PrivateTmp` — a private `/tmp`, so no cross-service temp-file attacks.
- `NoNewPrivileges` — no setuid escalation anywhere in this process tree.
- `RestrictNamespaces` — cannot create namespaces, i.e. cannot build a container to escape from.
- `CapabilityBoundingSet=` (empty) — **all** capabilities dropped.
- `SystemCallFilter=@system-service` — a syscall allowlist.

The audit below scores the real unit against thirteen of these.

<Callout kind="tip" title="The one that is missing, and why that is correct">
  The audit reports **12 of 13** present. The absent one is `MemoryDenyWriteExecute`, and the unit file explains it in a comment: numpy/BLAS — used both by the application and by learner exercise code executed in-process — hits W^X-incompatible codepaths under it. That is the right way to handle a control you cannot apply: omit it **deliberately** and record why, so the next reader knows it was decided rather than overlooked. An undocumented gap is indistinguishable from an oversight, and gets "fixed" by someone who then spends a day debugging BLAS.
</Callout>

## Summary

systemd supplies container-grade isolation without containers: a read-only filesystem, private `/tmp`, no new privileges, no namespaces, all capabilities dropped, and a syscall allowlist. The real unit scores **12 of 13**, and the missing `MemoryDenyWriteExecute` is omitted deliberately with the reason recorded in a comment — because an undocumented gap is indistinguishable from an oversight and invites someone to "fix" it into an outage.

<h2 id="intuition">Large-batch training on a GPU too small for a large batch</h2>

Large language models train best with very large batches — often millions of tokens per
optimizer step. Activations for a batch that size will not fit in GPU memory. **Gradient
accumulation** resolves this without compromise: run several small **micro-batches**, keep a
running average of their gradients, and step the optimizer only after the last one. Crucially,
the resulting update is not an approximation of the large-batch update — it is *numerically the
same update*.

<h2 id="math">Why the split is exact</h2>

The loss is a **mean** over the batch, and the derivative of a sum is the sum of derivatives, so
splitting a batch into `k` equal micro-batches and averaging their gradients is an algebraic
identity:

<MathBlock tex="\nabla_w \left[\frac{1}{N}\sum_{i=1}^{N} \ell_i\right] = \frac{1}{k}\sum_{j=1}^{k}\left(\nabla_w \left[\frac{1}{N/k}\sum_{i \in \text{micro}_j} \ell_i\right]\right)" />

Nothing is lost — provided the micro-batches are equal in size and you **average** rather than
sum.

<Callout kind="warning" title="The division is not optional">
  Forgetting to divide by the number of accumulation steps is the classic bug here. It does not
  crash, does not warn, and does not look wrong in the loss curve at first — it simply multiplies
  every gradient by `k`, which is exactly equivalent to multiplying the learning rate by `k`.
  On a run with 8 accumulation steps that is an 8× learning rate, and the first sign is usually
  a divergence you then misdiagnose as a bad learning-rate choice. The code below reproduces the
  bug and shows the ratio is precisely `k`.
</Callout>

<h2 id="python">Exact equivalence, the bug, and the memory trade</h2>

## Summary

Gradient accumulation splits a large batch into micro-batches and averages their gradients,
reproducing the full-batch gradient exactly — verified above to within `4.4e-16`, pure
floating-point round-off. Summing instead of averaging multiplies the gradient by precisely the
number of accumulation steps, silently scaling the effective learning rate by the same factor.
The trade is time for memory: peak activation memory scales with the micro-batch size, so a
smaller micro-batch buys headroom at proportionally more passes. The next lesson buys still more
memory by discarding activations and recomputing them.

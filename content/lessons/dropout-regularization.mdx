<h2 id="intuition">Forcing a network not to rely on any single neuron</h2>

Weight decay fights overfitting by penalizing weight *magnitude*. **Dropout** takes a
completely different approach: during training, randomly set some fraction of a layer's
activations to zero on every forward pass — a different random subset each time. This forces
the network to avoid **co-adaptation**: no single neuron can become so specialized that the
network relies on it being present, because on any given step, it might not be. The result
tends to be more redundant, more robust internal representations, since useful information ends
up spread across many neurons rather than concentrated in a few.

<h2 id="math">Inverted dropout</h2>

With dropout rate `p` (the probability of zeroing each activation), a **mask** of random 0s and
1s is generated each forward pass and multiplied elementwise into the layer's output:

<MathBlock tex="\text{mask}_i \sim \text{Bernoulli}(1-p) \qquad a_i^{\text{train}} = \frac{\text{mask}_i \cdot a_i}{1-p}" />

The division by `(1-p)` — "inverted" dropout — matters: with a fraction `p` of activations
zeroed, the *sum* of the layer's output shrinks by roughly that same fraction on average.
Dividing the kept activations by `(1-p)` rescales them back up, so the *expected* output
magnitude matches what it would be without dropout at all. This is specifically what lets
inference (evaluation/test time) skip dropout entirely — no mask, no rescaling, just the plain
forward pass — because training already corrected for the scale difference.

```python
# reference only -- torch isn't available in this browser sandbox
import torch.nn as nn

model = nn.Sequential(nn.Linear(10, 20), nn.ReLU(), nn.Dropout(p=0.5), nn.Linear(20, 1))
model.train()   # dropout is ACTIVE: random neurons zeroed each forward pass
model.eval()    # dropout is a no-op: the full network is used, unchanged
```

<Callout kind="tip" title="Why dropout must be OFF during evaluation">
  Applying random dropout at evaluation time would make predictions **non-deterministic** — the
  same input could produce different outputs on different calls, purely from randomness that has
  nothing to do with the actual input. `model.eval()` exists specifically to disable dropout (and
  batch normalization's training-only behavior, next lesson), guaranteeing a fixed, reproducible
  prediction for a fixed input — exactly what's needed once a model is actually being used, not
  trained.
</Callout>

## Summary

Dropout randomly zeroes a fraction `p` of a layer's activations on each training forward pass,
forcing the network away from relying on any single neuron (co-adaptation) and toward more
redundant, robust representations. Inverted dropout's `/(1-p)` rescaling keeps the *expected*
activation magnitude unchanged between training and evaluation — verified above by averaging
over many random masks — which is exactly what lets evaluation skip dropout entirely rather
than needing its own separate rescaling logic. The final regularization technique this week,
batch normalization, tackles a related but distinct problem: keeping each layer's input
distribution stable as training progresses.

<h2 id="intuition">Closing week one: the arithmetic that governs every agent</h2>

A step that works 95% of the time is a very good step. Chain twenty of them and the task succeeds about a third of the time. This is not a defect in any particular agent — it is what multiplication does, and it is the single most important constraint on agent design.

<h2 id="math">Reliability Multiplies</h2>

If steps fail independently with per-step success `p`, then over `n` steps:

<MathBlock tex="P(\text{task succeeds}) = p^{\,n}" />

The exponent is the problem. Going from `p = 0.95` to `p = 0.99` — an enormous improvement in a single step — takes a 20-step task from `0.358` to `0.818`, which is better but still not something you would deploy unattended. There is no value of `p < 1` that makes a long enough chain reliable.

<Callout kind="tip" title="The implication is architectural, not model-quality">
  Since `p^n` cannot be fixed by nudging `p`, the fix has to change the equation. Three things do: **fewer steps** (decompose better, batch independent work), **verifiable steps** (if a step's output can be checked, a failure can be caught and retried rather than propagating), and **idempotent retries** (so retrying is safe). Weeks three and four build all three, and measure how much each is worth.
</Callout>

  There is no language model in this browser, so the cell's *policy* — the part that decides what
  to do next — is a short deterministic function standing in for one. Everything **around** it is
  exactly what a production agent runs: the loop, the tool schemas, argument validation, the
  error-feedback path, the step budget, and the transcript. Those are the parts this month is
  about, and they are the parts that break in practice.

## Week one summary

An agent is a policy, tools, and a loop. Tools are schemas the model reads plus implementations it never touches; the dispatcher validates every proposed call and returns failures as text so the loop can recover — demonstrated by a malformed call being corrected on the next step. The loop's cost is `O(n²)` in tokens processed, measured at a **27×** gap between final transcript and total sent. And reliability compounds as `p^n`: a 95% step completes a 20-step task **35.8%** of the time. Week two attacks the `O(n²)`; weeks three and four attack the exponent.

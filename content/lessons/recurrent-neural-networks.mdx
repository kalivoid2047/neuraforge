<h2 id="intuition">A memory that carries forward, instead of a fixed window</h2>

N-gram models are trapped: a bigram sees one word back, a 5-gram sees four, and extending
further makes counts hopelessly sparse. A **recurrent neural network** breaks this by
maintaining a **hidden state** — a vector summarizing everything seen so far — that gets updated
at each token and carried forward. In principle, information from *any* earlier position can
persist in that state, with no fixed window and no exponentially-growing count table.

<h2 id="math">The recurrence relation</h2>

At each timestep `t`, the RNN combines the current token's embedding `x_t` with the previous
hidden state `h_{t-1}` to produce a new hidden state:

<MathBlock tex="h_t = \tanh(W_{xh}x_t + W_{hh}h_{t-1} + b_h) \qquad y_t = W_{hy}h_t + b_y" />

`y_t` are the output logits, which softmax turns into a next-token distribution. Crucially, the
**same** weight matrices `W_{xh}`, `W_{hh}`, `W_{hy}` are reused at *every* timestep — the
network learns one update rule and applies it repeatedly, rather than learning separate
parameters per position.

<Callout kind="tip" title="Weight sharing is what escapes the sparsity trap">
  An n-gram model must observe each specific n-gram to learn anything about it. An RNN instead
  learns a general *update rule* applied at every position, so patterns learned from one context
  transfer to others — and its parameter count stays fixed regardless of sequence length, rather
  than growing as `|V|^n`. This is the same weight-sharing idea that made convolution
  parameter-efficient in Month 4, applied along the time dimension instead of across an image.
</Callout>

<h2 id="python">An RNN forward pass over a sequence, implemented from scratch</h2>

np.max(z))\n    return e / e.sum()\n\ndef rnn_forward(tokens):\n    h = np.zeros(hidden_dim)   # initial hidden state: no memory yet\n    states, predictions = [], []\n    for token in tokens:\n        x = E[word_to_index[token]]                       # look up this token's embedding\n        h = np.tanh(x @ W_xh + h @ W_hh + b_h)            # THE recurrence: new state from input + old state\n        logits = h @ W_hy + b_y\n        states.append(h.copy())\n        predictions.append(softmax(logits))\n    return states, predictions\n\nsequence = [\"the\", \"cat\", \"sat\", \"on\"]\nstates, predictions = rnn_forward(sequence)\n\nprint(f\"sequence: {sequence}\")\nprint(f\"hidden state dimension: {hidden_dim}\")\nprint()\nfor t, (token, h, p) in enumerate(zip(sequence, states, predictions)):\n    top_idx = int(np.argmax(p))\n    print(f\"t={t} after '{token}':\")\n    print(f\"  hidden state: {h.round(3)}\")\n    print(f\"  predicted next token: '{vocab[top_idx]}' (p={p[top_idx]:.3f})\")\n\nprint()\nprint(\"the hidden state CHANGES at every step, carrying forward a summary of everything seen.\")\nprint()\n\n# demonstrate weight sharing: parameter count is INDEPENDENT of sequence length\nn_params = E.size + W_xh.size + W_hh.size + b_h.size + W_hy.size + b_y.size\nprint(f\"total parameters: {n_params}\")\nfor length in [4, 40, 4000]:\n    print(f\"  processing a {length}-token sequence still uses exactly {n_params} parameters\")\nprint()\nprint(f\"compare an n-gram table: a 5-gram model over this {V}-word vocabulary would need up to\")\nprint(f\"{V}^5 = {V**5} counts -- and that explodes as vocabulary or n grows.\")"}

## Summary

An RNN maintains a hidden state vector that is updated at each timestep from the current token's
embedding and the previous state, then used to predict the next token — with the *same* weight
matrices reused at every position. That weight sharing is what escapes the n-gram sparsity trap:
parameter count stays fixed regardless of sequence length (verified above: the same 121
parameters process a 4-token or a 4000-token sequence), while an n-gram table would grow as
`|V|^n`. The next lesson covers the vanishing gradient problem — the reason RNNs struggle in
practice with exactly the long-range dependencies they were designed to capture.

<h2 id="intuition">A neuron needs more than + and *</h2>

Recall the perceptron and activation functions from Month 2: a neuron computes a weighted sum
(`+` and `*` — already supported) and then passes it through a nonlinearity like `tanh` or
`ReLU`. To build a working neuron with this autograd engine, `Value` needs a few more
operations — and the pattern for adding each one is always the same: **implement the forward
computation, then attach a `_backward` closure implementing that operation's own local gradient
rule.** That pattern doesn't change no matter how exotic the operation is.

<h2 id="math">New local gradient rules</h2>

<MathBlock tex="\text{power: } \frac{d}{dx}x^n = nx^{n-1}" />
<MathBlock tex="\text{exp: } \frac{d}{dx}e^x = e^x" />
<MathBlock tex="\text{tanh: } \frac{d}{dx}\tanh(x) = 1 - \tanh^2(x)" />

The `tanh` rule is worth noting: its derivative can be written *in terms of its own output*
(`1 - tanh(x)²`), not just the raw input — so the `_backward` closure can reuse `out.data`
directly instead of recomputing `tanh` from scratch. That's a genuinely useful implementation
trick, not just a mathematical curiosity.

<h2 id="python">Adding pow, exp, and tanh to Value</h2>

<CodeCell

1)) * out.grad\n        out._backward = _backward\n        return out\n\n    def exp(self):\n        out = Value(math.exp(self.data), (self,), 'exp')\n        def _backward():\n            self.grad += out.data * out.grad   # d/dx[e^x] = e^x = out.data\n        out._backward = _backward\n        return out\n\n    def tanh(self):\n        t = math.tanh(self.data)\n        out = Value(t, (self,), 'tanh')\n        def _backward():\n            self.grad += (1 - t**2) * out.grad\n        out._backward = _backward\n        return out\n\n    def backward(self):\n        topo, visited = [], set()\n        def build_topo(v):\n            if v not in visited:\n                visited.add(v)\n                for parent in v._prev:\n                    build_topo(parent)\n                topo.append(v)\n        build_topo(self)\n        self.grad = 1.0\n        for v in reversed(topo):\n            v._backward()\n\ndef numerical_grad(f, x0, h=1e-6):\n    return (f(x0 + h) - f(x0)) / h\n\n# test 1: pow.  f(x) = x^3 at x=2\nx = Value(2.0)\ny = x ** 3\ny.backward()\nprint(\"pow:  x.grad =\", x.grad, \" numerical =\", round(numerical_grad(lambda v: v**3, 2.0), 4))\n\n# test 2: exp.  f(x) = e^x at x=1\nx2 = Value(1.0)\ny2 = x2.exp()\ny2.backward()\nprint(\"exp:  x.grad =\", round(x2.grad, 4), \" numerical =\", round(numerical_grad(math.exp, 1.0), 4))\n\n# test 3: tanh.  f(x) = tanh(x) at x=0.5\nx3 = Value(0.5)\ny3 = x3.tanh()\ny3.backward()\nprint(\"tanh: x.grad =\", round(x3.grad, 4), \" numerical =\", round(numerical_grad(math.tanh, 0.5), 4))"}

<Callout kind="tip" title="Division and subtraction come for free">
  With `__add__`, `__mul__`, and `__pow__` in place, `a - b` can be implemented as
  `a + (-1 * b)`, and `a / b` as `a * b**-1` — no new `_backward` rule needed for either. This is
  exactly the kind of composition the whole engine is built on: a small set of primitive
  operations with hand-written local gradients, and everything else built by combining them.
</Callout>

## Summary

Adding a new operation to the autograd engine always follows the same pattern: implement the
forward computation, then attach a `_backward` closure encoding that operation's local gradient
rule, verified against a numerical derivative. `pow`, `exp`, and `tanh` round out the set of
operations needed to build a real neuron (weighted sum plus nonlinearity) — exactly what the
next lesson does, composing these primitives into `Neuron`, `Layer`, and `MLP` classes.

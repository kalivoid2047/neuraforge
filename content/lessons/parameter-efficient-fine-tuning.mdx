<h2 id="intuition">Week two: adapting a model you cannot afford to move</h2>

Week one ended at an unsatisfying trade — adapt well and damage the model, or preserve it and adapt poorly. **Parameter-efficient fine-tuning** rejects both by freezing every pretrained weight and adding a small number of *new* trainable ones. The pretrained model cannot be damaged because it never changes, and adaptation happens in the added parameters.

<h2 id="math">Where the Memory Actually Goes</h2>

Month 8 measured full fine-tuning at 16 bytes per parameter: 2 for bf16 weights, 2 for gradients, and 12 for the fp32 master copy plus Adam's two moments. PEFT changes which of those scale with `N`:

<MathBlock tex="\text{mem} = \underbrace{2N}_{\text{frozen weights}} + \underbrace{14 \cdot N_{\text{trainable}}}_{\text{grads + master + Adam}}" />

The frozen weights still have to be stored, but the expensive per-parameter optimizer state now applies only to the tiny trainable set.

<Callout kind="tip" title="Why LoRA won over the rest of the PEFT family">
  Adapters insert bottleneck layers, prefix tuning prepends trainable KV vectors, prompt tuning prepends trainable embeddings — all work, and all add something to the model at inference time. LoRA's `BA` is a plain matrix product with the same shape as `W₀`, so after training it can be **folded in**: `W = W₀ + (α/r)BA` produces an ordinary weight matrix. Serving it costs exactly what serving the base model costs. The merge check below confirms the equivalence to `1.3e-15`.
</Callout>

## Summary

PEFT freezes every pretrained weight and trains a small number of added parameters, which collapses the memory cost because optimizer state — 12 bytes per parameter in Month 8's accounting — now applies to a fraction of a percent of the model. Measured for a 7B model: 112 GB full fine-tuning versus 14.1 GB for LoRA at `r=8`, an 87.4% reduction, with the remaining 14 GB being the frozen weights themselves. LoRA specifically wins because its adapter merges into the base weights exactly, verified to `1.3e-15`, leaving zero inference overhead. The next lesson looks at why the low-rank structure works.

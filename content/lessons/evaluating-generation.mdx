<h2 id="intuition">A correct answer and a grounded answer are not the same thing</h2>

A RAG answer can be correct but ungrounded (the model knew it from pretraining, and the citation is decorative), or grounded but wrong (the retrieved document was itself incorrect). Evaluation has to separate them, because they call for different fixes.

<h2 id="math">Is the Answer Supported?</h2>

**Groundedness / faithfulness** — is every claim supported by the retrieved context?

**Answer relevance** — does the answer address the question asked?

**Correctness** — is the answer true?

A crude but useful proxy for the first is the share of the answer's content terms appearing in the context:

<MathBlock tex="\text{support}(a,c) = \frac{|\,\text{terms}(a)\cap\text{terms}(c)\,|}{|\,\text{terms}(a)\,|}" />

<Callout kind="warning" title="The proxy is genuinely weak, and the measurement shows it">
  In the run below, a grounded answer scored `0.69` and a **hallucinated** one scored `0.60` — close enough that no threshold separates them cleanly. Term overlap cannot distinguish a true claim from a fluent false one built from the same vocabulary. What it does catch reliably is the abstention case at `0.17`, and answers whose content simply is not in the context at all. Production systems use an LLM judge for the harder discrimination — which brings its own reliability problems.
</Callout>

## Summary

Groundedness asks whether claims are supported by the retrieved context, which is distinct from correctness — an answer can be right but ungrounded, or grounded but wrong. Term overlap is a weak proxy: measured here, a grounded answer scored `0.69` against a hallucinated one at `0.60`, too close to separate, though it cleanly identified abstention at `0.17`. Abstention must count as success, since penalizing it pressures the system toward fabrication. The next lesson combines both halves.

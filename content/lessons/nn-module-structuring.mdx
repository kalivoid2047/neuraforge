<h2 id="intuition">You already built this — nn.Module just automates the bookkeeping</h2>

Month 3's `Neuron`, `Layer`, and `MLP` classes already did the real work: hold parameters,
implement a forward computation, and expose a `parameters()` method so an optimizer can find
every weight. `torch.nn.Module` is PyTorch's version of exactly this pattern, with one genuine
convenience added: **any `torch.Tensor` with `requires_grad=True` assigned as an attribute is
automatically registered**, so `.parameters()` collects every weight in the whole network —
including nested sub-modules — without you writing the manual list-concatenation Month 3's
`Layer.parameters()` and `MLP.parameters()` needed.

<h2 id="math">What nn.Module automates</h2>

Every `nn.Module` subclass follows the same two-method shape:

- **`__init__`** — declare the layers this module owns (each itself an `nn.Module`, like
  `nn.Linear`)
- **`forward`** — define how input data flows through those layers to produce output

```python
# reference only -- torch isn't available in this browser sandbox
import torch.nn as nn

class MLP(nn.Module):
    def __init__(self, n_in, n_hidden, n_out):
        super().__init__()
        self.layer1 = nn.Linear(n_in, n_hidden)   # automatically registers its weights + bias
        self.layer2 = nn.Linear(n_hidden, n_out)  # ditto

    def forward(self, x):
        x = self.layer1(x).tanh()
        return self.layer2(x)

model = MLP(3, 4, 1)
print(len(list(model.parameters())))  # 4: layer1's (weight, bias), layer2's (weight, bias)
```

Notice: no manual `parameters()` implementation needed, and no manual `.tanh()` bookkeeping —
`nn.Module.__setattr__` (called automatically whenever you write `self.layer1 = ...`) is what
does the registration, entirely behind the scenes.

<Callout kind="tip" title="forward() is called for you, via __call__">
  One more thing `nn.Module` provides: calling `model(x)` actually calls `model.__call__(x)`,
  which `nn.Module` implements to call your `forward(x)` method (plus some extra bookkeeping,
  like hooks, not relevant here). That's why real PyTorch code writes `model(x)` rather than
  `model.forward(x)` directly — both work, but `model(x)` is the correct, idiomatic form.
</Callout>

## Summary

`torch.nn.Module` automates the exact bookkeeping Month 3's `Layer` and `MLP` classes did by
hand: it intercepts attribute assignment (via `__setattr__`) to automatically register any
sub-module (or parameter) assigned to `self`, so `.parameters()` can walk the whole nested
structure without manual list-building. Every real PyTorch model follows the same two-part
shape — `__init__` declares layers, `forward` defines the computation — and calling `model(x)`
invokes `forward` indirectly through `__call__`. The next lesson looks at `nn.Linear` and
activation functions in more depth, the actual building blocks assigned inside `__init__`.

<h2 id="intuition">The failure mode is a critic that agrees with the mistake</h2>

The previous lesson's simulation treated detection as an independent parameter. In practice the critic is usually *the same model* that produced the work, and that breaks the independence assumption in the worst possible direction.

<h2 id="math">A Critic That Shares the Model's Blind Spots</h2>

The simulation assumed errors and detections were independent. When the critic is the same model, they are **correlated**: whatever caused the mistake — a misread requirement, a wrong assumption, missing knowledge — is equally present when reviewing it.

<MathBlock tex="d_{\text{effective}} \;\ll\; d_{\text{measured on independent errors}}" />

Self-critique catches *slips* — arithmetic, format, forgotten steps. It systematically misses **misunderstandings**, which are the errors that matter most.

<Callout kind="warning" title="Three conditions under which a critic is not worth adding">
  **1.** The critic shares the generator's blind spot — same model, same prompt, same missing context. **2.** The output is not checkable, so the critic can only express an opinion. **3.** Retries are not independent — re-running the same prompt at the same temperature reproduces the same answer, so a flagged step is re-done identically and the retry budget is spent for nothing. Under any of these the measured outcome is the weak-critic row: real cost, no gain.
</Callout>

## Summary

The reflection simulation assumed independent detection; a critic that is the same model violates that assumption in the worst direction, because whatever caused the error is equally present when reviewing it. Self-critique catches slips and misses misunderstandings. A critic is not worth adding when it shares the generator's blind spot, when the output is not checkable, or when retries are not independent — and the measured cost of adding one anyway is the weak-critic row: ~39% more calls for nothing.

<h2 id="intuition">Text classification was never a special case</h2>

Every piece needed for a neural text classifier already exists from Month 4: `nn.Linear`,
`ReLU`, softmax, cross-entropy loss, and Adam. The only genuinely new idea this month contributes
is the *input representation* — turning text into a fixed-length numeric vector (bag-of-words or
TF-IDF) that Month 4's machinery can consume exactly as if it were any other kind of numeric
feature vector, no different from the tabular examples used there.

<h2 id="math">Bag-of-words as a feature vector</h2>

A document's bag-of-words vector `x \in \mathbb{R}^{|V|}` (vocabulary size `|V|`) is fed
directly into a small feedforward network, exactly matching Month 4's architecture pattern:

<MathBlock tex="h = \text{ReLU}(xW_1+b_1) \qquad \text{logits} = hW_2+b_2 \qquad \hat{y}=\text{softmax}(\text{logits})" />

Trained with cross-entropy loss and Adam — precisely Month 4's `minimal-training-script`
pipeline, with a bag-of-words vector standing in for whatever numeric features were used there.

```python
# reference only -- torch isn't available in this browser sandbox
import torch.nn as nn

class TextClassifier(nn.Module):
    def __init__(self, vocab_size, hidden_size, n_classes):
        super().__init__()
        self.fc1 = nn.Linear(vocab_size, hidden_size)
        self.fc2 = nn.Linear(hidden_size, n_classes)
    def forward(self, bow_vector):
        h = torch.relu(self.fc1(bow_vector))
        return self.fc2(h)   # raw logits; nn.CrossEntropyLoss applies softmax internally
```

<Callout kind="tip" title="Naive Bayes vs. neural: an explicit model vs. a learned one">
  Naive Bayes explicitly estimates `P(word|class)` for every word and combines them via a fixed
  formula derived from Bayes' theorem — the decision process is fully interpretable. A neural
  classifier instead *learns* whatever weighted combination of bag-of-words features happens to
  minimize cross-entropy loss on the training data, with no explicit per-word probability
  ever computed. Both can perform well; they represent genuinely different modeling philosophies
  — explicit probabilistic structure versus a flexible, learned function.
</Callout>

## Summary

A neural text classifier is Month 4's exact architecture — `Linear → ReLU → Linear → softmax`,
trained with cross-entropy and Adam — applied to bag-of-words input vectors, verified above by
training one from scratch on a small spam/ham dataset. The only genuinely new ingredient is the
text-to-vector representation from earlier this month; nothing about the training pipeline
itself needed to change. This stands in contrast to Naive Bayes' explicit, interpretable
probability model — two different philosophies for the same task. The next lesson covers
choosing between approaches like these using the bias-variance framework, directly ahead of the
capstone.

<h2 id="intuition">Training doesn't generate token-by-token — it predicts everywhere at once</h2>

At inference time, a decoder generates one token, feeds it back in, generates the next, and so
on — genuinely sequential. Training does something much cheaper: it feeds the entire **correct**
target sequence in at once (this is why causal masking, from Week 1, is essential — otherwise
the model could just look ahead at the answer) and computes a loss at *every* position
simultaneously, in one forward pass. This is called **teacher forcing**: at each position, the
model is "forced" to condition on the true previous tokens, not its own (possibly wrong)
predictions.

<Callout kind="tip" title="Why this matters practically">
  Teacher forcing turns training a sequence model into something almost as parallelizable as
  training a plain classifier — one forward pass computes gradients for every position in the
  sequence at once, instead of needing `seq_len` sequential forward passes.
</Callout>

<h2 id="math">The shift-by-one setup</h2>

For next-token prediction, the input at position `i` should predict the token at position
`i+1`. Concretely, given a tokenized sequence `[t_0, t_1, ..., t_n]`:

<MathBlock tex="\text{input}=[t_0,\ldots,t_{n-1}], \qquad \text{target}=[t_1,\ldots,t_n]" />

Input and target are the *same sequence*, offset by one position. The loss at each position is
cross-entropy between the model's predicted next-token distribution and the actual next token:

<MathBlock tex="\mathcal{L}=-\frac{1}{N}\sum_{i} \log P(\text{target}_i \mid \text{input}_{\le i})" />

<Callout kind="danger" title="Pitfall: forgetting to exclude padding from the loss">
  If padding tokens are included in the loss average, the model gets gradient signal rewarding
  it for correctly predicting `<pad>` after `<pad>` — trivial to learn, and it dilutes the
  gradient signal for the tokens that actually matter, especially for short sequences padded to
  a long fixed batch length.
</Callout>

## Summary

Training uses teacher forcing: the true target sequence, shifted by one position, serves as
both input and label, letting one forward pass compute next-token predictions and loss for
every position simultaneously (safe only because of causal masking). Cross-entropy loss is
computed per position and must exclude padding tokens from the average, or the model gets
diluted and misleading gradient signal.

## Further reading

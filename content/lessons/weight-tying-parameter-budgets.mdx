<h2 id="intuition">The same matrix, used at both ends</h2>

A GPT needs two `vocab × d_model` matrices: the **embedding table** turning input token IDs into
vectors, and the **output projection** turning the final hidden state back into per-token logits.
**Weight tying** uses *one* matrix for both — the output projection is just the embedding matrix
transposed.

The justification is more than parameter-saving. The embedding row for a token is that token's
learned "meaning" vector; the output projection scores a hidden state against every token by dot
product. Using the same vectors for both means "which token does this hidden state most resemble"
is measured against exactly the same representations the model uses on input. Tying is a
statement that these should be the same space, not two independent ones.

<h2 id="math">Tying input and output</h2>

<MathBlock tex="\text{input: } h_0 = E[\,\text{token}\,] \qquad \text{output: } \text{logits} = h_L E^\top" />

One matrix `E`, used forward at the input and transposed at the output. Untied models learn a
separate `vocab × d_model` output matrix, costing exactly that many extra parameters.

<Callout kind="tip" title="Where a GPT's parameters actually live">
  Per transformer block: `4d²` for attention (`W_Q,W_K,W_V,W_O`), `2·d·d_ff` for the feed-forward
  network, and a negligible `4d` for the two LayerNorms. Since `d_ff` is conventionally `4d`, the
  FFN is `8d²` — **twice** the attention cost. The intuition that "a Transformer is mostly
  attention" is wrong on a parameter count: most of the weights are in the feed-forward layers.
</Callout>

## Summary

Weight tying reuses the embedding matrix as the output projection, saving `vocab × d_model`
parameters and asserting that input and output token representations should share one space.
Its benefit is largest for small models (28.3% of the tiny config) and shrinks with scale (5.1%
of the large one), because transformer blocks grow with depth and `d²` while the saving stays
fixed. The breakdown also corrects a common intuition: at `d_ff = 4d`, feed-forward layers hold
roughly twice the parameters attention does. The next lesson assembles all of this into a
complete GPT.

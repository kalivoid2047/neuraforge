<h2 id="intuition">Week three: building a real autograd engine, from scratch</h2>

Everything this month has been building toward this: a working implementation of reverse-mode
automatic differentiation, in plain Python, with no library doing the hard part for you. By the
end of this week you'll have a small engine that can compute gradients through arbitrary
arithmetic expressions — the same core idea that powers PyTorch's `.backward()`, just
implemented at a much smaller scale.

The foundation is a single class, usually called `Value`, that wraps a plain number and — every
time it's used in an operation — silently records *how it was produced*. That recorded history
**is** the computational graph from last week, built automatically as ordinary Python arithmetic
runs.

<h2 id="math">Design: a number plus a memory of its own construction</h2>

Each `Value` stores:

- `.data` — the actual number
- `._prev` — the `Value` objects that were combined to produce this one (empty for a leaf)
- `._op` — which operation produced it (e.g. `'+'`, `'*'`, or `''` for a leaf)
- `.grad` — the gradient accumulated so far (filled in during the backward pass, next lesson;
  starts at `0`)

The trick that makes this feel like ordinary Python: **operator overloading**. Defining
`__add__` and `__mul__` on the class means writing `a + b` for two `Value` objects
automatically creates a new `Value` *and* records that it came from an addition of `a` and `b`
— building the graph as a side effect of code that looks like normal arithmetic.

<Callout kind="tip" title="This is not yet an autograd engine">
  So far `Value` only builds the *forward* graph — it doesn't compute any gradients yet. That's
  entirely intentional: separating "build the graph" (this lesson) from "walk it backward to
  compute gradients" (next lesson) makes each piece easier to get right, and mirrors exactly how
  real frameworks structure the problem internally.
</Callout>

## Summary

The `Value` class wraps a plain number and, via operator overloading, automatically records the
computational graph (parents and operation) every time it's combined with another `Value` —
turning ordinary-looking arithmetic into graph construction as a side effect. This is the
forward half of an autograd engine; the next lesson adds the backward pass that actually
computes gradients by walking this recorded graph.

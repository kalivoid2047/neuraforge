<h2 id="intuition">It gets worse while you change nothing</h2>

A correct service stays correct. A model's accuracy decays as the world drifts away from its training distribution — with no code change, no failing test, and no alert. This is the one production failure mode that has no counterpart in ordinary software.

<h2 id="math">The Failure With No Software Analogue</h2>

Ground truth is rarely available in production, but the **inputs** always are. **Population Stability Index** compares the live input distribution to a reference:

<MathBlock tex="\text{PSI} = \sum_{i} (a_i - e_i)\,\ln\frac{a_i}{e_i}" />

over binned proportions. The conventional reading is `< 0.1` stable, `0.1–0.25` investigate, `> 0.25` retrain — and it is the symmetrized relative entropy you met in Month 5, reused as an operational alarm.

<Callout kind="warning" title="Every drift metric has a blind spot; know yours">
  Two rows of the measurement matter. The **same mean, wider spread** case scores `0.2011` and flags — a monitor watching averages would see nothing there. But the **moderate shift** case, a 0.25σ move, scores only `0.0568` and reads as *stable*. PSI is insensitive to modest mean shifts, so "stable" means "not detected by this test", never "nothing changed". And PSI cannot tell you accuracy dropped at all: it detects that the world moved, which correlates with degradation without being it. Treat it as a trigger for a labelled evaluation, not as a reason to retrain.
</Callout>

## Summary

Deploying a model differs from deploying code in one decisive way: it degrades over time with no change on your side. PSI detects input drift without labels, but has blind spots in both directions — it flagged an unchanged-mean spread increase at `0.2011` and read a 0.25σ shift as stable at `0.0568`. And it never proves accuracy dropped; it proves the world moved. The only real defence is a scheduled labelled evaluation, which is Month 9's discipline run on a cron.

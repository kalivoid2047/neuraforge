<h2 id="intuition">Evaluate each stage, then the whole</h2>

Stage metrics localize problems; an end-to-end metric tells you whether the system works. You need both, because a pipeline can have healthy-looking components and still fail, and a single end-to-end number cannot tell you where to look.

<h2 id="math">One Report, Several Stages</h2>

The report the capstone produces:

- **retrieval** — recall@k, MRR, per method
- **generation** — groundedness, citation rate, abstention correctness
- **end-to-end** — did the pipeline answer the question, and from the right source

Attribution rule: low recall is a retriever problem; high recall with low MRR is a ranking problem; good retrieval with a bad answer is a generation problem.

<Callout kind="warning" title="Report negative results">
  The capstone's comparison shows hybrid retrieval tying with fuzzy matching alone, and reranking changing **nothing**. Both are techniques this month recommended. Reporting them as wins because they are standard practice would be exactly the failure mode week four exists to prevent. On an 18-document corpus with untuned fusion weights, there is not enough signal for either to help — and saying so is the result.
</Callout>

## Summary

An end-to-end report combines retrieval metrics, generation metrics, and whole-pipeline outcomes, with a clear attribution rule: low recall implicates the retriever, high recall with low MRR the ranker, good retrieval with a bad answer the generator. This month's measurements include two negative results — hybrid search tying with a single method, and reranking changing nothing — both explained by an 18-document corpus rather than suppressed. The capstone assembles all of it.

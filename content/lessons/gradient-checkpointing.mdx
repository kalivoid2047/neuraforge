<h2 id="intuition">Throw activations away, then recompute them</h2>

Month 3's autograd engine had to keep every intermediate value from the forward pass, because
the backward pass needs them — the gradient of `a * b` with respect to `a` is `b`, so `b` must
still be around. For a 96-layer model on a long sequence, those stored activations dominate GPU
memory, often exceeding the weights by a wide margin.

**Gradient checkpointing** takes a deliberately wasteful-sounding approach: discard most
activations during the forward pass, keep only a few **checkpoints**, and when backward reaches
a discarded region, *recompute it* from the nearest checkpoint. It trades compute for memory,
and the exchange rate is unusually good.

<h2 id="math">The square-root optimum</h2>

Split `n` layers into `k` segments. You must store the `k` segment boundaries, plus — while
recomputing one segment — that segment's `n/k` internal activations:

<MathBlock tex="\text{memory}(k) = k + \frac{n}{k}" />

Minimizing over `k` (set the derivative `1 - n/k^2` to zero) gives:

<MathBlock tex="k^\star = \sqrt{n} \qquad \Rightarrow \qquad \text{memory} = 2\sqrt{n} = O(\sqrt{n})" />

Memory drops from `O(n)` to `O(√n)` — for a 96-layer model, from 96 stored activations to about
20.

<Callout kind="tip" title="Why the compute cost is 33%, not 100%">
  Checkpointing adds exactly one extra forward pass. That sounds like it should double the cost,
  but a backward pass costs roughly **twice** a forward pass (it computes gradients with respect
  to both inputs and weights). So a normal step is `1 + 2 = 3` units and a checkpointed step is
  `1 + 1 + 2 = 4` units — a **33%** increase, not 100%. That is the figure the code below
  computes, and it is why checkpointing is standard practice for large models rather than a
  desperate measure.
</Callout>

## Summary

Gradient checkpointing discards most activations during the forward pass and recomputes them
from stored checkpoints during backward. Storage is `k + n/k` for `k` segments, minimized at
`k = √n` — confirmed by scanning all values for a 96-layer model, where the minimum landed at
`k = 10` against `√96 ≈ 9.80`. That cuts stored activations from 96 to about 20 (79.6% saved)
for one extra forward pass, which — since backward costs roughly twice forward — is a 33%
compute increase rather than 100%. The next lesson moves beyond one device entirely.

<h2 id="intuition">Month 4: the same engine, industrial strength</h2>

Last month built a complete reverse-mode autograd engine from scratch — a `Value` class wrapping
scalars, recording operations, and computing gradients via a topologically-sorted
`backward()`. **PyTorch is that same idea**, generalized and industrialized in three specific
ways:

1. **Tensors instead of scalars** — a `torch.Tensor` is an N-dimensional array (like a NumPy
   array), so one node in the graph can represent an entire matrix or batch of data, not just
   one number.
2. **C++/CUDA instead of Python** — the actual arithmetic runs in compiled, GPU-accelerated
   code, not a Python loop, making it dramatically faster at scale.
3. **A much larger library of operations** — hundreds of pre-built, pre-differentiated
   operations (`nn.Linear`, `nn.Conv2d`, and hundreds more), each with a hand-optimized local
   gradient rule, saving you from writing a `_backward` closure for every operation yourself.

Nothing conceptually new is being introduced. `requires_grad=True` is "start recording, like our
`Value.__init__`." `.backward()` is "walk the graph in reverse topological order, exactly like
last month." `.grad` is "the accumulated gradient, exactly like `Value.grad`."

Reference PyTorch code for the exact expression built by hand last month, `z = (x + y) * x`:

```python
# reference only -- torch isn't available in this browser sandbox, see Callout above
import torch

x = torch.tensor(3.0, requires_grad=True)
y = torch.tensor(4.0, requires_grad=True)
a = x + y
z = a * x
z.backward()

print(z.item())    # 21.0
print(x.grad.item())  # 10.0
print(y.grad.item())  # 3.0
```

## Summary

PyTorch's `torch.Tensor` and `.backward()` implement exactly the reverse-mode autograd algorithm
built by hand last month, generalized from single scalars to N-dimensional tensors and
implemented in optimized, GPU-capable C++/CUDA rather than a Python loop. Because this lesson
platform's interactive code runs in a browser-based Python (Pyodide) that doesn't include
PyTorch, this month's PyTorch snippets are reference-only — every interactive `CodeCell` instead
verifies the same underlying concept with real, runnable Python or NumPy. The next lesson looks
at the tensor itself: shape, dtype, and the device concept that lets the same code run on a CPU
or a GPU.
